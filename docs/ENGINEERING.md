# 统一工程规范

两个 OpenCode 插件共享本规范；各仓库保留一份相同正文，修改公共规则时须同步另一仓库。项目功能、稳定标识及实现细节以各自 ARCHITECTURE.md 为准。

## 架构契约

依赖方向固定为 `入口 → 适配层 → core`。入口只导出插件；`core` 负责数据校验、目录解析及有界 HTTP 客户端，不导入宿主 SDK；`server` 负责公开 SDK、凭据、注册、刷新与生命周期。需要交互时增加 `tui` 和 `rpc`，TUI 通过 RPC 访问服务端状态，不直接写 storage。

网络访问必须有明确触发点、目标、超时、响应大小限制与重定向策略。凭据不进入模型元数据、日志、错误或测试证据。新资源必须有释放路径；初始化失败、刷新失败与持久化失败须分别说明状态影响。架构文档必须区分当前实现和后续设计目标。

| 设计点     | Headers                            | Magpie                              |
| ---------- | ---------------------------------- | ----------------------------------- |
| 状态权威源 | 宿主 storage 中的路由配置          | Magpie 目录，进程内快照             |
| 更新触发   | 用户 RPC save / refresh / discover | 启动与定时轮询                      |
| 一致性     | revision 检测、单实例写入队列      | 单飞刷新、签名去重、reload 失败回滚 |
| 交互       | TUI + RPC + Server                 | Server + 宿主原生选择器             |
| 凭据来源   | 宿主 integration                   | 插件选项或服务端环境变量            |
| 分发       | 宿主加载 TypeScript 源码           | 编译为 dist JavaScript              |

这些差异保留。不得为统一目录而引入无用途的 UI、RPC、存储层或共享运行时包。SDK 依赖分类、测试框架与构建策略根据加载契约管理，不以表面一致为目标。

## 开发流程

1. 阅读 AGENTS.md、本文、ARCHITECTURE.md 和 DEVELOPMENT.md；检查工作区已有修改。
2. 明确触发条件、期望行为、影响的稳定契约与验证方式，再做最小改动。
3. 修改配置或可观察行为时同步测试、配置参考、架构说明及 CHANGELOG；迁移必须说明旧数据和回滚。
4. 按影响执行下面的验证层级；记录命令、环境、结果和未覆盖范围。
5. 检查 diff、版本、文档链接和包内容；不擅自提交、发布或修改用户全局配置。

插件版本严格固定为 `0.1.0`（展示为 `v0.1.0`），只有用户明确要求才能更新。package.json、锁文件根包、包检查、文档和制品必须一致；SDK、宿主与配置 schema 独立管理。保留现有 strict 类型检查和测试框架，不用 any 或忽略类型错误掩盖 SDK 不兼容。

## 验证与授权

| 层级       | Headers                 | Magpie                      | 边界                                           |
| ---------- | ----------------------- | --------------------------- | ---------------------------------------------- |
| 本地基础   | npm run verify          | npm run verify              | 类型、逻辑；HTTP 仅本地模拟                    |
| 附加组件   | npm run test:tui        | 无独立 TUI                  | Headers 需要 Bun                               |
| 包检查     | npm run check:package   | npm run check:package       | 导出、版本与产物检查的实际覆盖以工具为准       |
| 无模型宿主 | npm run test:host:smoke | npm run test:host           | 独立配置、数据库、端口；不发送生成请求         |
| 模拟生成   | npm run test:host       | npm run test:host:inference | 即使 localhost，也需要用户明确授权模型调用测试 |
| 真实生成   | 另行约定受控步骤        | node tools/verify-live.mjs  | 用户明确授权后才执行                           |

命令名不能代替工具审查：两个仓库的 `test:host` 含义不同。当前任务禁止执行任何模型调用测试，包括模拟生成；真实远端目录发现和真实凭据测试也不属于默认验证。依赖安装可能访问包注册表，不代表模型测试授权。无模型宿主验证必须先审查工具和隔离配置，防止加载日常插件产生额外访问。

文档检查不能证明运行时兼容，打包成功不能证明宿主加载，目录注册不能证明 TUI 刷新或模型可用。验证失败或环境缺失应原样记录，不将跳过写成通过。不把历史测试数量、旧宿主证据当作本次结论。

## 文档职责

| 文档                     | 唯一职责                                         |
| ------------------------ | ------------------------------------------------ |
| AGENTS.md                | 自动化代理约束、禁止操作、必读入口与项目特有契约 |
| README.md / README.en.md | 功能与最短上手路径；关键事实双语对齐             |
| docs/README.md           | 文档索引与阅读顺序                               |
| docs/ENGINEERING.md      | 两仓库共同架构规则、开发流程和验证分级           |
| docs/ARCHITECTURE.md     | 当前模块、数据流、生命周期、状态与失败语义       |
| docs/DEVELOPMENT.md      | 本项目环境、真实脚本、调试和修改步骤             |
| CONTRIBUTING.md          | 提交范围、评审与变更同步要求                     |
| docs/VALIDATION.md       | 指定环境下的验证证据及未测项                     |
| docs/RELEASING.md        | 发布门禁、制品与回滚                             |

深度文档使用简体中文，命令优先 PowerShell，代码标识保留原文。示例只使用占位符。规范写长期规则，验证文档写带环境和结果的证据，不将本机临时路径写成通用安装要求。新增文档须进入索引；相对链接须可解析。修改公共规范时同步两份正文并核对差异；项目专属说明放回本项目文档。
