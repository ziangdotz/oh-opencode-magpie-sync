# 运行规范

本文覆盖上线后的日常运行：健康检查、变更、凭据轮换、容量、事故处置与下线。首次部署见 [部署与验收](DEPLOYMENT.md)。

## 1. 运行基线

| 项目 | 值 |
| --- | --- |
| 插件 | v0.1.0 |
| 宿主 | OpenCode 2.4.2 |
| SDK | 2.4.2 |
| 运行形态 | OpenCode 服务端插件（后台服务或 `--standalone`） |
| 目录来源 | 远端 Magpie `<baseURL>/models` |
| 目录持久化 | 无（仅内存） |
| 默认刷新 | 30 秒 |
| 默认发现超时 | 5 秒 |

## 2. 服务生命周期

```powershell
opencode service status
opencode service restart
opencode models
```

- **启动**：加载插件 → 注册 provider → 首次发现（失败不阻止启动）→ 启动轮询。
- **运行**：按周期发现；变化时提交注册表；失败保留旧目录。
- **停止/重启**：清空内存目录；新进程重新发现。
- **卸载**：停止定时器、等待有界发现、释放鉴权钩子与 provider 注册。

`--standalone` 进程需要单独管理，不受 `opencode service` 控制。不要在未确认进程模型的情况下同时操作两者。

## 3. 健康信号

| 信号 | 位置 | 正常 | 异常含义 |
| --- | --- | --- | --- |
| `Catalog synced: N models` | 服务日志 | 首次加载或目录变化后出现 | 长期不出现可能无变化或发现失败 |
| `Initial discovery unavailable` | 服务日志 | 偶发一次 | 启动时网关不可达；后续轮询会重试 |
| `Refresh failed; keeping last catalog` | 服务日志 | 断网期间可出现 | 当前目录仍可用，但已不是最新 |
| `magpie/*` 条目 | `opencode models` | 存在且数量合理 | 缺失时检查配置、路径、服务是否重启 |
| 进程稳定性 | 服务状态 | 无崩溃循环 | 可能为包加载失败或宿主不兼容 |

日志中的发现错误经过收敛，可能不含 HTTP 状态。需要精确定位时按 [故障排查](TROUBLESHOOTING.md) 在本机受控验证，不要在工单中粘贴完整响应。

## 4. 例行检查

建议纳入日常巡检：

| 频率 | 检查 |
| --- | --- |
| 每日 | 服务状态；`opencode models` 是否仍有 `magpie/*`；错误日志是否突增 |
| 每周 | 目录模型数量与 Magpie 侧对比；抽查显示名与 ID |
| 每月 | 凭据有效期；包目录权限；备份可恢复性 |
| 每次变更 | 按 [部署与验收](DEPLOYMENT.md) 执行无生成验收并记录 |

不要通过频繁重启来“修复”目录问题；先确认是网络、凭据、URL 前缀还是宿主传播问题。

## 5. 变更管理

### 5.1 允许的变更

- 修改 `baseURL`、`gatewayKey`、`refreshSeconds`、`timeoutMs`；
- 更新插件构建产物或包路径；
- 升级宿主/SDK（需走兼容性流程）。

以上变更均需重启宿主才会生效。修改配置前备份（受控目录，含密钥）。

### 5.2 变更窗口

- 模型目录增删由 Magpie 侧完成，插件自动同步，无需重启。
- 插件配置、版本、宿主升级应在维护窗口执行。
- 变更后至少观察一个完整刷新周期与一次目录核对。

### 5.3 记录内容

- 变更前后版本（插件、宿主、SDK）；
- 配置差异（脱敏）；
- 执行命令与结果；
- 未覆盖项与回滚点。

## 6. 凭据轮换

推荐使用服务进程环境变量 `MAGPIE_GATEWAY_KEY`，由服务管理器注入。

1. 在 Magpie 侧创建新 Key，保留旧 Key 直到验证完成。
2. 更新服务环境或 `options.gatewayKey`。
3. 重启宿主。
4. 确认 `opencode models` 正常、日志无鉴权错误。
5. 吊销旧 Key。
6. 记录轮换时间与执行人，不记录密钥本身。

注意：

- JSON 中的 Key 是明文，修改后需重启；
- 新 shell 的环境变量不会影响已运行服务；
- 环境变量更新不会覆盖非空 `options.gatewayKey`。

## 7. 容量与性能

| 因素 | 影响 | 建议 |
| --- | --- | --- |
| 模型数量 | 目录解析、注册表 reload 成本 | 数百模型通常无压力；持续增长时观察 reload 频率 |
| 刷新周期 | 网关请求量与目录新鲜度 | 稳定环境用 60–300 秒；频繁变更用 10–30 秒 |
| 发现超时 | 慢链路上的失败率 | 跨广域网可提高到 10–20 秒 |
| 响应大小 | 8 MiB 上限 | 超限会失败并保留旧目录；需优化网关返回 |
| 目录变化频率 | reload 次数 | 仅 ID/名称/限额变化触发；顺序变化不触发 |

插件不缓存到磁盘，不产生持续后台任务（仅定时器）。发现请求串行合并，不会因慢网关堆积并发。

## 8. 事故处置

| 场景 | 立即动作 | 后续 |
| --- | --- | --- |
| 目录突然为空 | 确认是否连续两次有效空响应；检查 Magpie 目录 | 恢复上游后等待下一周期；必要时重启 |
| 目录长期不更新 | 检查日志、网络、凭据；对比 Magpie | 修复后观察 `Catalog synced` |
| 401/403 | 检查 Key 来源与优先级、服务环境 | 轮换或修正配置后重启 |
| provider collision | 查找重复注册来源 | 保留一个来源，移除其余 |
| 宿主启动失败 | 回滚插件包与配置 | 收集脱敏日志，按兼容性流程排查 |
| TUI 看不到新模型 | 确认服务端已 `Catalog synced` | 重新打开 `/models`；记录宿主传播问题 |
| 推理失败但目录正常 | 检查模型权限、上游健康、协议能力 | 属网关/模型问题，不是目录同步问题 |

详细症状表见 [故障排查](TROUBLESHOOTING.md)。

## 9. 与其他 Provider 共存

- 本插件只注册 `magpie`，不修改默认模型，不影响其他 provider。
- 切回 Ollama 等本地 provider：在 `/models` 选择对应模型即可；如不再需要 Magpie，移除插件条目并重启。
- 不要删除其他 provider 的配置或凭据。
- 不要同时加载其他注册 `magpie` 的插件。

## 10. 备份与恢复

| 对象 | 是否备份 | 注意 |
| --- | --- | --- |
| `opencode.json` | 是 | 可能含明文密钥，存受控目录 |
| 插件包目录/制品 | 是 | 保留可回滚版本与锁文件 |
| 服务环境变量 | 由服务管理器管理 | 不写入工单 |
| 插件内存目录 | 否 | 重启后重新发现 |
| OpenCode 数据库 | 按宿主策略 | 不要为排障随意删除 |

恢复时优先恢复“旧包 + 匹配锁文件 + 旧配置”，再重启并验证目录。

## 11. 下线

1. 通知使用方模型将不可用。
2. 从 `opencode.json` 移除插件条目（或指向旧 provider）。
3. 重启服务。
4. 确认 `magpie/*` 条目消失，其他 provider 正常。
5. 吊销 Gateway Key。
6. 归档脱敏后的变更记录与制品校验值。

## 12. 运维边界

- 不保证所有目录模型均可生成；可用性由 Magpie 与上游决定。
- 不提供 SLA、自动扩缩容、跨重启缓存或目录一致性证明。
- 发现失败时的“保留旧目录”是可用性措施，不表示目录仍然正确。
- 任何真实生成验证都会产生上游用量，应单独授权与记录。
